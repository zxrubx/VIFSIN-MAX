# Bot MAX Institute

Бот в мессенджере MAX для приёма обратной связи от студентов (жалобы, вопросы, конфликты) с веб-админкой для модерации.

## Возможности
- Диалог `/report`: категория → описание → контакт (или `-` для анонимного обращения)
- Анонимность по-настоящему: у анонимного обращения аккаунт MAX автора **не сохраняется**
- `/status ID` — узнать статус обращения (работает и для анонимных)
- Автору с контактом бот сам пишет при смене статуса в админке
- Уведомление сотрудникам о новом обращении (`NOTIFY_USER_IDS`)
- `/privacy` — как используются данные; лимит обращений в час; ограничения длины текста
- Админка: счётчики и фильтр по статусам, одобрить / отклонить / решено

## Установка

Нужен Python 3.10+ (требование `maxapi`).

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_PASSWORD
```

## Запуск

```bash
python -m bot.main                                            # бот (polling)
uvicorn admin.app:app --host 127.0.0.1 --port 8000            # админка, отдельный процесс
```

Админка: http://127.0.0.1:8000, логин `admin`, пароль из `ADMIN_PASSWORD`.
Со слабым паролем (`admin`, `change_me`, пустой) она не запустится.

Или через Docker: `docker compose up -d --build` (БД лежит в `./data`).

## Как получить токен бота

Бота в MAX может создать только зарегистрированный в РФ **самозанятый, ИП или юрлицо** — просто физлицо нельзя.
Порядок: https://dev.max.ru/docs/chatbots/bots-create/create

1. Профиль на платформе MAX для партнёров (self-service: https://business.max.ru), верификация через Госуслуги.
2. Создать карточку бота, указать контакт поддержки и политику обработки данных (текст из `/privacy` — основа).
3. Дождаться модерации (до 48 рабочих часов) и получить токен → в `.env` как `BOT_TOKEN`.

Пока нет токена, всё можно проверить локально через тесты.

## Ограничения
- Состояния диалога (FSM) и лимиты хранятся в RAM — после перезапуска бота незавершённый диалог придётся начать заново.
- Админка использует HTTP Basic Auth с одним пользователем. Наружу — только за reverse proxy с HTTPS.
- В обращениях могут быть персональные данные: если бот будет работать официально, оформите согласие/политику по 152-ФЗ и ограничьте доступ к `data/`.
